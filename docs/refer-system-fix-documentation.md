## 1. Executive Summary

The referral (invite) system of ANDOS was broken at **four independent levels**. A user opening a referral link (e.g. `https://andostpsite.vercel.app#ref=neha-chx`) did get the code stored locally, but:

1. **No Firebase record** was ever created for the referral (code to do so did not exist).
2. **No Telegram notification** was ever sent to the owner (the notification function existed but was never called).
3. The **user profile document itself was failing to be created** in Firestore because `saveUser()` wrote fields that the security rules forbid — so even `refBy` never reached Firebase.
4. **Share links generated by the app did not contain the ref parameter** — so links shared from the app could never be tracked in the first place.

All four problems were fixed in a single commit. After the fix, the full pipeline works:

```
Friend opens #ref=CODE link
  → code captured to localStorage (existing logic, unchanged)
  → friend logs in with Google
  → referrals/{uid} document created in Firestore (immutable signup record)
  → users/{uid}.refBy + .referralCode written (profile doc now actually saves)
  → "🤝 NEW USER VIA REFERRAL" card sent to owner's Telegram (via CF Worker proxy)
```

## 2. Architecture Overview (as it exists in code)

| Component | Location in `index.html` | Role |
|---|---|---|
| Ref capture | IIFE ~line 12643 | On page load, parses `?ref=` / `#ref=` from URL, stores in `localStorage['andos_ref_by']` (first impression wins) |

| Personal code generation | IIFE ~line 12945 | Generates each user's own code from name (e.g. `NEHA123`); fallback `ANDOS2026` |
| `buildRefLink()` | ~line 12908 | Builds the user's personal share URL: `base + '#ref=' + code` (base = `CONFIG.referralLink` = `https://tinyurl.com/Andos-i`) |
| Telegram secure proxy | fetch interceptor ~line 12538 | Rewrites every `api.telegram.org/bot…` fetch to `workerUrl/<method>` (JSON). Bot token lives **only** in the Worker env — never in the browser |
| `tgCard()` | ~line 12895 | Sends formatted HTML card to owner chat (chat id `6775379996`) through the proxy |
| Firebase sync layer | `window.ANDOS_FB` ~line 14663 | `saveOrder`, `saveTransaction`, `saveWallet`, `saveUser`, `applyCloud`, `watchOrders`, `watchRequests` — **now also `saveReferral`** |
| Login gate | `onAuthStateChanged` ~line 14995 | Google sign-in (popup → FedCM → redirect fallback). On success: `loadUser` → `applyCloud` → `saveUser` → **referral hook (new)** |

**Referral data model (defined by the security rules):**

- `referrals/{inviteeUid}` — one **immutable** signup record per user. Created by the invitee themselves, only on their own UID path. This is *attribution only* — it does not authorize any reward/payout (per rule comments).
- `users/{uid}` — profile document; includes `refBy` (code that referred this user) and `referralCode` (this user's own code).

## 3. Root-Cause Analysis — Bugs Found (before the fix)

### Bug 1 — `notifyRef()` was dead code (never called)
A full function `window.notifyRef(kind, extra)` existed (line ~12910) that builds and sends:

```
🆕 ACCOUNT CREATED
👤 Name: …  📱 Mobile: …  🎫 User Code: …
🤝 Referral: neha-chx   🕐 12 Oct 2026, 10:30
```

…but **zero call sites existed anywhere in the app**. A comment even said *"signup alert ab saveOnboard se — har user ke liye"* — pointing to `saveOnboard` as the trigger.

### Bug 2 — `saveOnboard()` was an empty stub
```js
window.saveOnboard = function () {};   // line 15745 — no-op
```
The function that was *supposed* to fire the signup notification was hollow. **Result: no Telegram referral message was ever sent.**

### Bug 3 — No Firebase referral-save code existed at all
`ANDOS_FB` (the sync layer) covered `orders`, `transactions`, `wallets`, `support_tickets`, `requests`, `users` — but **there was no code anywhere that wrote referral data to Firestore**. The ref code lived only in `localStorage['andos_ref_by']` (device memory — lost on cache clear / new phone). Referral *earnings* state (`andos_referral_state`) was also localStorage-only. **Result: "refer Firebase mein save nahi ho raha".**

### Bug 4 — `saveUser()` wrote rule-forbidden fields → user doc creation always failed
The (recently hardened) security rules allow only these profile fields on `users/{uid}`:

```
uid, email, googleName, googlePhoto, username, photoURL, name, mobile, dob,
ffUid, ffName, bio, location, website, createdAt, lastSeen, lastLogin,
logins, updatedAt, device, refBy, referralCode, avatar
```

…but `saveUser()` was also sending: `wallet`, `loyalty`, `walletUnlocked`, `ddUsed`, `walletPin`, `favorites`, `transactions`, `ordersCount`.

- On **create**, the rule `request.resource.data.keys().hasOnly(profileFields())` → **denied** (the document could never be created).
- On **update**, `diff(resource.data).affectedKeys().hasOnly(profileFields())` → denied whenever any forbidden field changed (transactions/favorites grow over time → frequent denials).

All failures were silently swallowed by `.catch(e => console.warn('FB saveUser', e))`. **Result: not even `refBy` could land in Firestore — the whole user profile sync was dead.**

### Bug 5 — Share links carried no ref parameter
- Telegram share button (line ~23377) shared `CONFIG.siteUrl` (plain) — the code was only in the *caption text*.
- WhatsApp / native share sheet (lines ~23371, 23381, 24992) shared `CONFIG.referralLink` = `https://tinyurl.com/Andos-i` — **no `#ref=CODE`**.
- Profile QR code (line ~23064) encoded the plain short link.

**Result: links shared from the app could never be attributed** — the recipient's session would have no ref at all.

> Verified working (no fix needed): the Cloudflare Worker proxy (`andos-tg-proxy`) was live and correctly forwarding to the Telegram API with a valid bot token; ref **capture** from the URL into localStorage already worked.

## 4. Fixes Applied (commit `1557286`)

### Fix 1 — `ANDOS_FB.saveUser()` cleaned to rules-compliant fields

Removed all rule-forbidden fields (`wallet`, `loyalty`, `walletUnlocked`, `ddUsed`, `walletPin`, `favorites`, `transactions`, `ordersCount`). Kept profile fields, added `referralCode`:

```js
ANDOS_FB.saveUser = function (extra) {
    if (!this.ready() || !auth.currentUser || auth.currentUser.isAnonymous) return Promise.resolve();
    var u = auth.currentUser;
    // SECURITY RULES: sirf profileFields() likhne ke liye allowed hai.
    // wallet/loyalty/walletPin/favorites/transactions/ordersCount = server (Admin SDK) only —
    // client se likhne par pura document write permission-denied ho jata tha.
    var data = Object.assign({
        uid: u.uid, email: u.email || '', googleName: u.displayName || '', googlePhoto: u.photoURL || '',
        username: user.username || '', photoURL: user.photoURL || '',
        name: user.name || '', mobile: user.mobile || '', dob: user.dob || '',
        ffUid: user.ffUid || '', ffName: user.ffName || '',
        bio: user.bio || '', location: user.location || '', website: user.website || '',
        refBy: (window.getRefBy ? window.getRefBy() : ''), referralCode: (CONFIG.referralCode || ''),
        avatar: (function () { try { var a = localStorage.getItem('andos_profile_avatar') || ''; return a.length < 900000 ? a : ''; } catch (e) { return ''; } })(),
        device: this.deviceId(), lastSeen: Date.now(), updatedAt: Date.now()
    }, extra || {});
    return db.collection('users').doc(u.uid).set(data, { merge: true })
        .catch(function (e) { console.warn('FB saveUser', e); });
};
```

**Effect:** `users/{uid}` documents now actually get created/updated; `refBy` (who referred this user) and `referralCode` (this user's own code) persist in Firestore.

### Fix 2 — New `ANDOS_FB.saveReferral(code)` (immutable signup record)

Written to match the security rules **exactly**:

```js
// ---- REFERRAL ATTRIBUTION (Firebase): har user ka ek immutable signup record ----
// Rules: referrals/{inviteeUid} — exactly 5 fields, createdAt == request.time
// (isliye serverTimestamp() zaroori hai), sirf member (non-guest) apne own UID pe.
ANDOS_FB.saveReferral = function (code) {
    if (!this.ready() || !auth.currentUser || auth.currentUser.isAnonymous) return Promise.resolve();
    code = String(code || '').trim();
    if (!/^[A-Za-z0-9_-]{3,64}$/.test(code)) { console.warn('FB saveReferral: invalid code', code); return Promise.resolve(); }
    var uid = auth.currentUser.uid;
    var docRef = db.collection('referrals').doc(uid);
    return docRef.get().then(function (d) {
        if (d.exists) return null; // first referral wins — record immutable hai
        return docRef.set({
            referredUid: uid,
            referralCode: code,
            status: 'signup',
            source: 'web',
            createdAt: firebase.firestore.FieldValue.serverTimestamp()
        });
    }).catch(function (e) { console.warn('FB saveReferral', e); });
};
```

Rule-compliance checklist:

| Rule requirement | How it's satisfied |
|---|---|
| `create` only on own UID path | `db.collection('referrals').doc(auth.currentUser.uid)` |
| `hasOnly` + `hasAll` exactly 5 fields | Document contains **only** `referredUid, referralCode, status, source, createdAt` |
| `referredUid == inviteeUid` | Set to the same UID as the doc path |
| `referralCode.matches('^[A-Za-z0-9_-]{3,64}$')` | Pre-validated with the same regex before writing |
| `status == 'signup'`, `source == 'web'` | Hardcoded constants |
| `createdAt == request.time` | `FieldValue.serverTimestamp()` — only a server-set timestamp equals `request.time` in rules (a client `Date.now()` would always fail) |
| No update/delete ever | Function never updates; `get()` first → skip if doc exists |

### Fix 3 — Referral hook in the auth flow (Firebase save + Telegram trigger)

Inserted in `onAuthStateChanged` → after `applyCloud()` completes:

```js
// ---- REFERRAL ATTRIBUTION: Firebase mein save + Telegram par notify ----
try {
    var __refCode = (window.getRefBy ? window.getRefBy() : '');
    if (__refCode) {
        try { ANDOS_FB.saveReferral(__refCode); } catch (e2) {}
        if (isNew) {
            try { window.tgCard('🤝', 'NEW USER VIA REFERRAL', [
                ['Name', fbUser.displayName],
                ['Email', fbUser.email],
                ['Ref Code', __refCode, 'code'],
                ['UID', fbUser.uid, 'code'],
                ['Device', ANDOS_FB.deviceId(), 'code']
            ], 'referred signup'); } catch (e2) {}
        }
    }
} catch (e) {}
```

Behavior:
- **Every login** (new or returning): if a ref code exists in localStorage, ensure the immutable `referrals/{uid}` record exists (idempotent — first ref wins, no duplicate writes).
- **New users only** (`isNew`): send the `🤝 NEW USER VIA REFERRAL` card to the owner's Telegram. Returning users don't re-trigger the card (no spam).
- The card travels through the existing secure fetch interceptor → Cloudflare Worker → Telegram Bot API (token never touches the browser).

### Fix 4 — Copy-link button now copies the personal ref link
`copyReferralLink()` now uses `buildRefLink()` instead of the plain short link → copies `https://tinyurl.com/Andos-i#ref=USERCODE`.

### Fix 5 — `shareReferralChannel()` (WhatsApp / Telegram / share sheet)
All three channels now share `_refLink = buildRefLink()`:
- **WhatsApp:** `shareWithImage(_refLink, text)` (fallback `wa.me` text unchanged).
- **Telegram:** `https://t.me/share/url?url=<#ref=CODE link>&text=Use referral code CODE` — previously the URL was plain `CONFIG.siteUrl`, so the ref was lost.
- **Native share sheet:** `openAndosShareSheet(_refLink, …)`.

### Fix 6 — Profile-page share (`shareReferralPage()`)
Both branches (with/without `navigator.share`) now use `buildRefLink()`.

### Fix 7 — Profile QR code
`initProfileReferralQr()` previously encoded `siteUrl + '/refer?code=…'` (a broken path on the tinyurl short link) / plain short link. It now encodes `buildRefLink()` — scanning the QR lands on the site **with the owner's `#ref=CODE` attached**.

## 6. End-to-End Flow After the Fix

1. Owner opens Profile → Shares/Copies link → link is `…#ref=NEHA123` (all channels + QR).
2. Friend taps the link on any device → on load, `#ref=NEHA123` parsed → `localStorage['andos_ref_by'] = 'NEHA123'` (existing logic).
3. Friend signs in with **Google**.
4. On auth state change:
   - `loadUser` → `applyCloud` (profile merge) → `saveUser` → **`users/{uid}` doc created with `refBy: 'NEHA123'` + `referralCode`** (Fix 1).
   - `saveReferral('NEHA123')` → **`referrals/{uid}` doc created** with the 5 rule-compliant fields (Fix 2 + Fix 3).
   - Since `isNew === true` → **Telegram card `🤝 NEW USER VIA REFERRAL`** delivered to owner (Fix 3).
5. Later logins of the same friend: `saveReferral` is a no-op (doc exists) — attribution stays immutable.

**Referral code format:** `^[A-Za-z0-9_-]{3,64}$` (e.g. `neha-chx` ✅, `NEHA123` ✅, `ANDOS2026` ✅).

## 8. Constraints & Design Notes

| # | Note |
|---|---|
| 1 | **Only Google-signed-in (member) users are attributed.** Per the security rules, `guest()`/anonymous sessions cannot create `users` or `referrals` docs. Guests still work locally (localStorage), but their ref won't persist server-side. |
| 2 | **First ref wins, forever.** `referrals/{uid}` is create-only (no update/delete allowed by rules). A user who first logged in *without* a ref cannot later be attributed to one. |
| 3 | **Attribution only — no payouts.** The `referrals` collection records *who invited whom*; reward crediting/withdrawals remain the server/Admin-SDK domain (per rule comments). The in-app referral earnings UI (`andos_referral_state`) is still device-local. |
| 4 | **Wallet/loyalty/PIN/favorites/transactions are no longer client-writable** (by design of the new rules). They are frozen on the `users` doc; cross-device sync of financial state must go through the **Admin SDK (your Worker)**, not the browser. `applyCloud` already handles missing cloud values safely (falls back to local). |
| 5 | **Ref code in URL is client-capturable by design.** Any user can open a link with a chosen `#ref=` value on a fresh browser; that's inherent to client-side attribution. The rules mitigate abuse: only one record per real (Google) UID, immutable, and reward logic is server-side. |
| 6 | **TinyURL fragment:** `https://tinyurl.com/Andos-i#ref=CODE` works because browsers preserve the URL fragment across redirects — the fragment never hits the tinyurl server and is appended to the final landing URL. |
| 7 | **Offline writes:** if a user logs in offline, `serverTimestamp()` writes queue in the Firestore offline cache; on reconnect the server stamps them with `request.time`, so the rule still passes. |
